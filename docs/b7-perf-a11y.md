## 一、做了哪些（不做无数据的优化）

| 问题 | 实测影响 | 处理 |
| --- | --- | --- |
| 图谱布局 O(n²) × 110 次迭代 | 900 节点约 8900 万次距离计算，主线程卡死 | 加确定性预算：>120 节点按比例减迭代，>400 节点只用圆周初值 |
| 大图没有提示 | 用户以为图坏了 | 超过预算时显示「图谱较大（N 个节点）：布局精度已自动降低」 |
| 弹窗只能点关闭 | 键盘无法关闭、焦点会跑到背后页面 | 统一 `useDialogA11y`：Escape 关闭、初始焦点进弹窗、Tab 循环、关闭后焦点归还触发元素 |
| 放大/缩小按钮只有「+/-」 | 读屏只念「加号」 | 补 `aria-label` / `title` |
| 图谱 SVG 无描述 | 读屏无法理解画布 | `role="img"` + 「知识图谱，共 N 个节点、M 条连线」 |
| 图谱节点只能用鼠标 | 无法键盘选择 | `role="button"`、`tabIndex=0`、Enter/Space 选择、`aria-pressed` |
| 深度按钮无状态语义 | 读屏不知当前层级 | `aria-pressed` |
| 状态消息不播报 | 读屏静默 | `role="status"` + `aria-live="polite"` |

`useDialogA11y` 已接入：AI 设置、AI 草稿、质量分析、数据与备份、同步、版本历史。

**刻意没做**：图谱虚拟化（当前布局已是瓶颈，渲染 900 个 SVG 节点仍可接受）、
向量索引分表（会引入 schema v8 与迁移风险，等真实规模再说）、引入 a11y 测试库。

3. 未做自动化 axe 扫描；a11y 覆盖集中在键盘与语义标签，颜色对比度沿用原设计。
4. 900 节点测试只断言耗时上限，未做渲染帧率测量。
