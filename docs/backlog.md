## B-1 按设备独立 token（原 Phase 4.7）⏸ 暂缓

- **目标**：一设备一票，吊销设备时作废它的凭证；服务端校验 token 与 deviceId 绑定，
  换 deviceId 也无法绕过吊销。
- **现状**：全局 Bearer token + deviceId 黑名单（4.1）。吊销能清掉旧记录、拦住同一 deviceId，
  但拿同一 token 换 deviceId 仍可同步（见 `phase4-1-device-revocation.md` 的边界）。
- **暂缓理由**：当前是单人 tailnet 使用，设备不对外、没有转手/丢失风险；完整方案有
  「换票失败锁死设备同步」的迁移风险，收益不抵成本。
- **候选方案**（重启时再选）：
  - A 完整：签发设备 token，设备换票后只保留设备 token；二维码带管理 token，手机换票后丢弃；旧配置自动迁移。
  - B 保守：老设备继续用全局 token，新扫码设备用设备 token，吊销只对设备 token 生效（零锁死风险、收益有限）。
- **重启条件**（任一）：设备可能丢失/转手；需要给他人设备；token 曾泄露；入口开放到公网；
  与他人共用服务器。

## B-2 自有域名 + Let's Encrypt 第二入口（原 Phase 4.8）⏸ 暂不做

- **目标**：Tailscale 之外的入口，更低依赖 tailnet 客户端。
- **现状**：负责人 2026-11-12 明确「暂时不买域名」，本项保留为未完成、不开工。
- **说明**：PWA 与 MCP 的落地不再依赖本项，已划入 Phase 5 计划（`docs/phase5-plan.md`）；
  本项只解决「入口归属 / 去 Tailscale 依赖 / 第三方访问」。
- **重启条件**：决定购买域名，或需要给不属于自己 tailnet 的设备/服务访问。

## B-3 画布布局跨设备同步 / 进入备份

- **现状**：`canvas_cards` 只存本机（schema v6）；连线（手动关系）会同步。
- **暂缓理由**：不同屏幕摆放不同，强行同步会互相覆盖；先观察实际使用频率。
- **重启条件**：多设备都常用画布，或换机后抱怨布局丢失。

## B-4 跨笔记后台预取附件

- **现状**：只预取当前打开笔记的缺失附件（并发 2、单篇 10 MB，4.6）。
- **暂缓理由**：后台替用户消耗流量不礼貌，且当前笔记/附件量级小。
- **重启条件**：弱网下频繁连续打开多篇含附件的笔记、影响阅读体验。

## B-5 服务器端加密存储

- **现状**：sqlite 与附件文件明文（OPEN-001=A 允许），依赖 tailnet/HTTPS 传输层。
- **暂缓理由**：单人自有服务器，威胁模型暂未覆盖。
- **重启条件**：服务器迁到不可信主机、多人共用、或要求「运维也看不到内容」。

## B-6 加密备份的密钥轮换 / 恢复码重置

- **现状**：OPEN-011 B 基线通过（加密、跨设备恢复、目录写入）；密钥轮换未做。
- **暂缓理由**：属增强项，不影响现有备份可用性。
- **重启条件**：恢复码曾外传、需要定期轮换、或多人持有口令。
