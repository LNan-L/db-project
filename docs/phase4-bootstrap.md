## 立项理由

Phase 3 收口时确认：手机（390px 竖屏）上侧栏与编辑器仍并排，编辑器被压到约 100px，正文逐字换行；`responsive.spec.ts` 只覆盖 1280px。同步能力已经可用，但**手机端不可用**是当前最大的产品短板。

## 范围（按顺序交付）

### A1 窄屏单栏布局（先做）

- ≤ 720px 时：侧栏与编辑器单栏排列，选中笔记后进入全屏编辑器，并提供「返回列表」
- 正文正常换行（不再逐字一行）
- 验收：新增 `tests/e2e/mobile-layout.spec.ts`（390×844 视口）：列表 → 选中 → 编辑器占满宽度 → 返回列表；正文渲染宽度 > 240px

### A2 手机同步配置（二维码 / 一键导入）

- PC 侧本地生成包含「服务器地址 + token」的二维码/一键链接（不联网、不回传）
- 手机扫码即写入同步配置，不再手填 64 位 token
- 验收：单元测试覆盖载荷编码/解码；E2E 覆盖 PC 侧二维码渲染与「复制配置链接」

### A3 附件下载进度与失败重试

- 打开含远端附件的笔记时显示下载进度（已下载 / 总大小）
- 失败可手动重试，并在同步面板可见
- 验收：单元测试覆盖进度回调与重试计数；E2E 覆盖占位 → 完成的状态切换

## 已知风险

1. **临时隧道域名会变 = origin 会变**：手机上旧的 IndexedDB 数据「看不见」（数据仍在旧 origin），同步配置也要重填。A2 的扫码配置能降低重配成本，但**不能消除 origin 漂移**；若要长期使用，仍需回到「稳定入口」议题。
2. 1 Mbps 上行：附件按需下载可用，批量附件不可行。
3. 窄屏改造可能影响桌面布局 —— 用 1280px 的既有 E2E 作回归闸门。
