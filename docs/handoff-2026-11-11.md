`pull` 原用 `updated_at`（内容时间）当游标 → 已同步设备拉不到后补的旧内容。现改为 `synced_at`（服务端接收时间），启动自动迁移回填，游标单调递增。回归检查 `server/verify-pull-since.js`（旧代码 2 FAILED，新代码 ALL PASS），生产迁移日志 `synced_at backfilled for 5 notes`。

## 六、已知风险 / 边界

- 服务器明文存储；OPEN-001=A 允许，但传输依赖 SSH 隧道 / 临时 HTTPS。
- 1 Mbps 带宽：文本够用，附件慢；PWA 首载 3.2 MB 预缓存，手机上要等 1–2 分钟。
- Tailscale 固定域名解决 origin 漂移；备用临时隧道仍会变域名（旧 IndexedDB 数据"看不见"，数据仍在旧 origin）。
- `tailscale serve`（仅 tailnet）稳定；`funnel`（公网）在大陆网络实测 20% 请求超时、单请求 3–6 秒，**不作默认入口**，手机主用 pinggy。
- 游标类故障：本地 0 篇 + 有游标 → 客户端自动全量拉；「全量重同步」只在空设备可用（本地有笔记时已禁用，否则会把未改动内容当冲突回推）。
- 附件二进制与版本历史尚未同步；自动同步/重试/离线已实现。
- 客户端判断"远端脏"仍用内容时间 `updatedAt`：回填的旧内容能拉到并新增，但本地已有同 ID 且内容不同时保守不覆盖。
- 服务器 token 只存本地；不要写进仓库或聊天。
