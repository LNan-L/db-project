## 二、已定原则（2026-11-12）

1. **不买域名、不开放公网**：继续用 Tailscale（4.8 暂缓，见 `docs/backlog.md` B-2）。
2. **MCP 只对 tailnet / 本机开放**，不暴露公网。
3. **PC 端 PWA 的问题并入 Phase 5 解决**（见第 3 节）。
4. AI / MCP 的所有写入先产出草稿，用户确认后才落库（与 REQ-205/302 一致）。

## 三、配套事项 5-PWA：PC 端的 PWA

现状：手机走 `https://….ts.net` 已是完整 PWA（可安装、离线、SW 更新正常）；
PC 走 `http://127.0.0.1:5273`（vite dev），`devOptions.enabled: false` → 不注册 Service Worker，
没有真正的安装/离线。

两个可选做法（都不需要域名）：

| 方案 | 做法 | 注意 |
| --- | --- | --- |
| A 用 tailnet 入口 | PC 直接打开 `https://….ts.net`，与手机同款 PWA | 换 origin：先同步、再切换；旧 origin 数据不会自动迁移 |
| B 本地预览 | `npm run build && npm run preview`，打开 `http://127.0.0.1:4273`（localhost 是安全上下文） | 同样是新 origin，需要一次同步迁移 |

迁移步骤（两方案通用）：在 5273 点「立即同步」确认全部上云 → 新入口打开 → 填/扫同步配置 →
全量拉取 → 对比笔记数（当前 4 篇）与附件 → 确认后切换；旧 origin 保留只读，不删除。

验收建议：PC 上可「安装」应用；断网可读可写；关掉浏览器完全重启后数据仍在。

## 四、配套事项 5-MCP：MCP 接口（REQ-302）

部署形态（建议优先 A）：

- **A 本机 stdio MCP server（PC）**：Claude Desktop 等本机客户端以 stdio 启动；进程内部调同步 API /
  本地导出数据，不监听端口、不暴露网络。
- **B ECS 上的 HTTP/SSE MCP**：走 tailnet（`http://10.0.0.10:8080/mcp` 或 ts.net），
  不开放公网；需要 `pke-web` 增加 `/mcp` 反代。

认证：沿用现有 Bearer token（4.7 按设备 token 暂缓，风险已知）。MCP 写操作必须额外授权，
不能只靠 token：

- 搜索 / 读取：可直接执行；
- 草稿写入：返回草稿对象，**不落库**；用户确认后由客户端调用正式写接口；
- 正式写入：需要显式确认参数（如一次性 nonce）+ 写 `audit_logs`（时间、工具、参数摘要、结果）。

工具集草案：`search_notes`、`read_note`、`list_tags`、`draft_note`、`draft_relation`、
`list_quality_candidates`。

## 五、待决问题（立项前必须定）

1. **模型来源**：云端 API 还是本地模型？笔记内容是否允许出本机？（决定隐私与架构）
2. **向量存储**：本地 IndexedDB 还是服务端 sqlite？嵌入模型/维度怎么选。
3. **AI 建议的交互**：草稿区、对比视图、一次生成多条？
4. **质量分析阈值**（REQ-304）：重复/孤立的判定规则。
5. **MCP 客户端范围**：只 Claude Desktop，还是通用客户端。
6. **成本/配额**：云端模型费用上限。

## 六、本阶段不做

- 域名 / 公网入口（4.8 暂缓）。
- 多人协作与权限体系。
- 按设备独立 token（4.7 暂缓）；MCP 的写授权先用「确认令牌 + audit_logs」，不改全局认证。

## 七、建议的推进顺序（等立项）

1. 先定「模型来源 + 数据出不出本机」——这一条决定后面所有架构。
2. REQ-301 语义混合检索（全文已有，补向量，可降级）。
3. REQ-205 草稿助手（依赖检索）。
4. REQ-302 MCP（依赖检索/草稿 + 授权审计）。
5. REQ-304 质量分析（独立，可并行）。
6. 5-PWA 随任一阶段顺手做（不阻塞 AI）。
